--------------------------------------------------------------------------------
1. WHAT THIS MODULE DOES
--------------------------------------------------------------------------------
For every official (employee) in the Indian Official Statistical System:
  1. Compute the skill gap between what their job role requires (Dataset 2)
     and what they currently have (Dataset 3, quiz-verified preferred over
     self-rated).
  2. Recommend training courses from the catalogue (Dataset 4) that close
     the largest gaps, ranked by a weighted tag-overlap score (Tier 1) and
     optionally blended with semantic embedding similarity (Tier 2).
  3. Explicitly report gaps that have NO course coverage (e.g. S014 Cloud
     Computing) instead of silently dropping them.

OUT OF SCOPE (do not build): MCQ/quiz generator, frontend/dashboards, real
iGOT Karmayogi integration, authentication. Dataset 4 is the mock catalogue.

4. THE PIPELINE
--------------------------------------------------------------------------------
STAGE A - Data loading (once, at startup)
  4 CSVs -> repositories -> parse packed fields -> validate foreign keys.

STAGE B - Skill-gap calculation (per employee)
  role requirements (D2) - employee's current levels (D3)
  quiz_verified_skills preferred over self_rated_skills when both exist
  gap = required_level - current_level ; keep only gap > 0
  sort largest gap first
  output: [{skill_id, skill_name, current_level, required_level,
            gap, priority_weight}]

STAGE C - Course matching (per employee)
  Tier 1 (always): tag-overlap
    courses whose skill_tags hit the gap skills
    score = sum(priority_weight of matched gaps) * level relevance
    return top-N (default 5)
  Tier 2 (optional, behind config flag): semantic
    embed course descriptions once at startup (all-MiniLM-L6-v2)
    embed each gap skill as "{skill_name}: {description}"
    cosine similarity blended with Tier-1 score for final ranking

STAGE D - Unmatched gaps (required behaviour)
  A gap skill with zero matching courses (S014 today) must return:
    {"skill_id":"S014","skill_name":"Cloud Computing",
     "status":"no_courses_available",
     "message":"No courses currently available for Cloud Computing. This gap
                has been flagged for the training team."}
  Never crash, never silently omit, never invent a course.

STAGE E - API layer (3 endpoints, JSON)
  GET /employees/{employee_id}/gaps
  GET /employees/{employee_id}/recommendations?top_n=5
  GET /employees/{employee_id}/profile
  404 for unknown employee_id; 422 for bad top_n.

STAGE F - Sanity checks (automated in tests/)
  1. Fully-qualified employee -> empty/short gaps, empty/minimal recs.
  2. Employee gapped on S014 -> explicit no_courses_available response.
  3. Typical mixed employee -> courses tagged with their gap skills rank
     near the top.

--------------------------------------------------------------------------------
5. KEY DESIGN DECISIONS
--------------------------------------------------------------------------------
1. TIER 2 IS OPTIONAL AT RUNTIME.
   Embeddings behind a config flag. If sentence-transformers is missing, the
   service boots on Tier 1 only (warning logged) instead of crashing. Tier 1
   alone passes all three sanity checks. Keeps dev setup light and gives a
   fallback if the model download fails in a deploy environment.

2. EMBEDDINGS PRECOMPUTED ONCE, NOT PER REQUEST.
   784 course descriptions embedded into an in-memory matrix at startup (or
   via a dedicated precompute script). Requests only embed one short text per
   gap skill and do a matrix multiply - milliseconds, not seconds.

3. CORS ENABLED FROM DAY ONE.
   The full-stack frontend will call this from a different origin. Configurable,
   not locked to localhost.

4. STABLE RESPONSE SHAPES AS THE INTEGRATION CONTRACT.
   The three endpoint shapes are the contract for the frontend team. FastAPI's
   /docs (Swagger) + /openapi.json serve as the live source of truth.

5. DEFENSIVE DATA HANDLING.
   All foreign keys are currently valid (verified programmatically), but the
   loader validates on read and logs - the code must not assume the datasets
   stay clean if edited later.

  this dataset version.
- Level values consistently 1-3 across D2 and D4.
- A handful of course descriptions are placeholder/low-information (e.g.
  C001). Treated as normal data; Tier-1 tag scoring carries them.
